# 1. 개발자 환경 구축

## 1.1 운영체제 기초

### 1) 운영체제의 역할

운영체제(OS)는 하드웨어 자원을 관리하고 응용 프로그램이 실행될 환경을 제공하는 시스템 소프트웨어다.

| 구성 요소   | 역할                    |
| ------- | --------------------- |
| 프로세스 관리 | 프로세스 생성, 종료, 스케줄링     |
| 메모리 관리  | 메모리 할당, 회수, 가상 메모리 관리 |
| 파일 시스템  | 파일 및 디렉터리 관리          |
| 장치 관리   | 입출력 장치와 드라이버 관리       |
| 네트워크 관리 | 네트워크 인터페이스와 통신 지원     |
| 보안 및 보호 | 사용자 권한과 자원 접근 제어      |

### 2) 운영체제 종류 및 특징

| 종류      | 주요 특징                           |
| ------- | ------------------------------- |
| Windows | GUI 중심, 일반적인 데스크톱 및 서버 환경       |
| Linux   | 오픈소스, 서버 및 시스템 개발 환경에서 널리 사용    |
| Unix    | 다중 사용자·다중 작업 환경을 지원하는 운영체제 계열   |
| RTOS    | 정해진 시간 제약 내에서 작업을 처리하는 실시간 운영체제 |
| 임베디드 OS | 특정 장치와 목적에 맞게 설계된 운영체제          |

**실시간 운영체제(RTOS)**는 무조건 처리 속도가 빠른 운영체제를 뜻하지 않는다. 작업을 정해진 시간 내에 처리하는 예측 가능성과 시간 제약 준수가 중요하다.

### 3) CLI 주요 명령어

| 목적          | Linux       | Windows CMD   |

### 4) 프로세스 우선순위

프로세스 스케줄링은 CPU를 어떤 프로세스에 할당할지 결정하는 과정이다.

* **FCFS**: 먼저 도착한 프로세스부터 실행한다.
* **SJF**: 실행 시간이 짧은 프로세스를 먼저 실행한다.
* **SRTF**: 남은 실행 시간이 가장 짧은 프로세스를 선택한다.
* **Priority Scheduling**: 우선순위가 높은 프로세스를 먼저 실행한다.
* **Round Robin**: 각 프로세스에 일정한 시간 할당량(Time Quantum)을 부여한다.

**기아현상(Starvation)**은 특정 프로세스가 자원을 계속 할당받지 못하는 현상이다.

**에이징(Aging)**은 오래 기다린 프로세스의 우선순위를 점진적으로 높여 기아현상을 방지하는 기법이다.

### 5) 프로세스와 스레드

| 구분    | 프로세스              | 스레드                    |
| ----- | ----------------- | ---------------------- |
| 실행 단위 | 독립적인 프로그램 실행 단위   | 프로세스 내 실행 단위           |
| 주소 공간 | 일반적으로 독립          | 같은 프로세스의 스레드끼리 공유      |
| 자원    | 독립적인 자원과 실행 상태    | 스택·레지스터 등 실행 상태는 별도    |
| 통신    | IPC 등 별도 통신 수단 필요 | 공유 메모리 등을 통한 통신이 쉬움    |
| 장애 영향 | 다른 프로세스와 격리 가능    | 같은 프로세스의 다른 스레드에 영향 가능 |

멀티스레딩은 한 프로세스 안에서 여러 실행 흐름을 수행하는 방식이다. 스레드가 공유하는 데이터에 동시에 접근하면 경쟁 상태가 발생할 수 있으므로 동기화가 필요하다.

## 1.2 기본 개발환경 구축

* **컴파일러**: 소스 코드를 목적 코드 또는 실행 가능한 코드로 변환한다.
* **인터프리터**: 프로그램을 해석하고 실행한다. 실제 구현은 언어와 실행 환경에 따라 다르다.
* **어셈블러**: 어셈블리어를 기계어로 변환한다.
* **링커**: 목적 파일과 라이브러리를 결합한다.
* **로더**: 실행 파일을 메모리에 적재하고 실행을 준비한다.
* **디버거**: 중단점, 변수 값, 호출 스택 등을 이용해 실행 상태를 분석한다.
* **빌드 도구**: 컴파일, 테스트, 패키징 등의 작업을 자동화한다.

### 오류의 종류

| 오류     | 의미                     | 예시                  |
| ------ | ---------------------- | ------------------- |
| 컴파일 오류 | 문법 또는 타입 등 컴파일 단계의 문제  | 선언되지 않은 변수 사용       |
| 런타임 오류 | 실행 중 발생하는 문제           | 0으로 나누기, 잘못된 메모리 접근 |
| 논리 오류  | 실행은 되지만 결과가 잘못됨        | 잘못된 계산식             |
| 링크 오류  | 외부 함수·라이브러리 등을 연결하지 못함 | 정의되지 않은 함수 참조       |

언어와 실행 환경에 따라 구체적인 오류 분류는 달라질 수 있다.

# 2. 컴퓨터 프로세서 및 명령어

## 2.1 연산 장치와 레지스터

### 1) CPU의 주요 구성 요소

| 구성 요소   | 역할                         |
| ------- | -------------------------- |
| ALU     | 산술 연산과 논리 연산 수행            |
| CU      | 명령어 해석 및 각 장치의 동작 제어       |
| 레지스터    | CPU 내부에서 데이터·주소·상태를 빠르게 저장 |
| PC      | 다음에 실행할 명령어의 주소를 보관        |
| IR      | 현재 해석하거나 실행할 명령어를 보관       |
| MAR     | 메모리에 접근할 주소를 보관            |
| MDR/MBR | 메모리에서 읽거나 메모리에 쓸 데이터를 보관   |
| SP      | 스택의 현재 위치를 관리              |
| 상태 레지스터 | 연산 결과의 상태 플래그 등을 보관        |

**ALU가 자주 사용하는 상태 플래그**

* Zero Flag(ZF): 결과가 0인지 나타낸다.
* Carry Flag(CF): 자리올림 또는 자리내림 관련 상태를 나타낸다.
* Sign Flag(SF): 결과의 부호 비트 상태를 나타낸다.
* Overflow Flag(OF): 부호 있는 연산에서 표현 범위를 넘었는지 나타낸다.

Carry와 Overflow는 서로 다른 개념이다. 부호 없는 연산의 자리올림과 부호 있는 연산의 오버플로를 구분해야 한다.

### 2) 주요 어셈블리 명령어

| 명령어                  | 의미                       |
| -------------------- | ------------------------ |
| MOV                  | 데이터 이동                   |
| LOAD                 | 메모리에서 레지스터로 데이터 읽기       |
| STORE                | 레지스터 등의 데이터를 메모리에 저장     |
| ADD / SUB            | 덧셈 / 뺄셈                  |
| MUL / DIV            | 곱셈 / 나눗셈                 |
| AND / OR / XOR / NOT | 논리 연산                    |
| CMP                  | 두 값을 비교하고 상태 플래그 설정      |
| JMP                  | 무조건 분기                   |
| JZ / JE              | 0 또는 같음 조건에서 분기          |
| JNZ / JNE            | 0이 아님 또는 다름 조건에서 분기      |
| CALL                 | 서브루틴 호출                  |
| RET                  | 서브루틴에서 복귀                |
| PUSH                 | 스택에 데이터 저장               |
| POP                  | 스택에서 데이터 꺼내기             |
| INT                  | 인터럽트 또는 소프트웨어 인터럽트 관련 동작 |

명령어의 세부 동작과 길이는 CPU 아키텍처 및 명령어 집합에 따라 달라진다.

### 3) CALL과 RET

일반적인 서브루틴 호출 흐름은 다음과 같다.

1. CALL 실행 시 복귀 주소를 저장한다.
2. PC를 서브루틴 시작 주소로 변경한다.
3. 서브루틴 실행이 끝나면 RET을 실행한다.
4. 저장된 복귀 주소로 돌아간다.

**기출 주의:** CALL 주소가 1234라고 해서 무조건 복귀 주소가 1235인 것은 아니다. 명령어 길이가 1바이트라는 조건이 있어야 1235가 된다. 일반적으로 복귀 주소는 CALL 다음 명령어의 주소다.

### 4) 중첩 호출과 재귀 호출

* **중첩 서브루틴 호출(Nested Call)**: 서브루틴 A가 실행 중 서브루틴 B를 호출한다.
* **재귀 호출(Recursive Call)**: 함수가 자기 자신을 다시 호출한다.

둘 다 여러 호출 단계의 복귀 정보를 관리해야 한다. 일반적으로 스택을 이용해 호출별 복귀 주소와 실행 상태를 보관한다.

### 5) 주소선과 주소 공간

주소선이 \(n\)개이고 각 주소 조합이 하나의 주소를 나타낸다면 표현 가능한 주소 수는 다음과 같다.

$$
N=2^n
$$

반대로 주소 가능한 개수가 \(N\)개라면 필요한 주소선 수는 다음과 같다.

$$
n=\log_2 N
$$

예시:

* 주소 가능한 위치가 256개라면 \(2^8\)이므로 8개 주소선이 필요하다.
* 4KB 메모리를 바이트 단위로 주소 지정하면 \(4096=2^{12}\)이므로 12비트 주소가 필요하다.

단, 주소 지정 단위가 바이트인지 워드인지 확인해야 한다.

## 2.2 명령어 제어와 마이크로 오퍼레이션

### 1) 명령어 실행 사이클

일반적인 명령어 실행은 다음 단계로 설명할 수 있다.

1. **Fetch**: 메모리에서 명령어를 가져온다.
2. **Decode**: 명령어를 해석한다.
3. **Execute**: 지정된 연산을 수행한다.
4. **Memory Access**: 필요하면 메모리에 접근한다.
5. **Write Back**: 결과를 레지스터 등에 기록한다.

모든 명령어가 위의 모든 단계를 동일하게 사용하는 것은 아니다.

### 2) 마이크로 오퍼레이션

마이크로 오퍼레이션은 레지스터 전송이나 산술·논리 연산처럼 CPU 내부에서 수행되는 기본 동작이다.

예를 들어 메모리에서 명령어를 가져오는 과정을 단순화하면 다음과 같이 나타낼 수 있다.

* \(MAR \leftarrow PC\)
* \(MDR \leftarrow M[MAR]\)
* \(IR \leftarrow MDR\)
* \(PC \leftarrow PC + 1\)

실제 순서와 세부 동작은 CPU 설계에 따라 달라질 수 있다.

## 2.3 파이프라인과 병렬 실행

### 1) 파이프라인

명령어 실행 단계를 겹쳐 실행하여 처리량을 높이는 기법이다.

예를 들어 4단계 파이프라인은 여러 명령어가 서로 다른 단계에서 동시에 진행될 수 있게 한다.

이상적인 단일 발행 파이프라인에서 명령어 \(N\)개와 단계 \(K\)개가 주어지면 필요한 사이클 수는 다음과 같다.

$$
K+N-1
$$

이는 파이프라인 채우기와 비우기 비용을 포함하고, 정지나 분기 실패가 없는 이상적인 조건이다.

### 2) Superscalar

한 사이클에 여러 명령어를 발행할 수 있는 구조다.

* 1-wide: 한 사이클에 최대 1개 발행
* 4-wide: 한 사이클에 최대 4개 발행
* 5-wide: 한 사이클에 최대 5개 발행

이상적인 \(W\)-wide 파이프라인에서 \(N\)개 명령어와 \(K\)단계가 주어지면:

$$
K+\left\lceil \frac{N}{W}\right\rceil-1
$$

예를 들어 5-wide, 4단계 파이프라인에서 15개 명령어라면:

$$
4+\left\lceil\frac{15}{5}\right\rceil-1=6
$$

**주의:** 이 식은 명령어 발행 폭과 파이프라인 단계가 주어진 이상적인 문제에 적용한다. 실제 CPU의 성능은 명령어 의존성, 자원 충돌, 분기 실패 등에 영향을 받는다.

### 3) 파이프라인 해저드

| 종류      | 원인                   | 예시 또는 대응           |
| ------- | -------------------- | ------------------ |
| 구조적 해저드 | 하드웨어 자원 충돌           | 자원 추가, 실행 지연       |
| 데이터 해저드 | 명령어 사이의 데이터 의존성      | Forwarding, Stall  |
| 제어 해저드  | 분기 등으로 다음 실행 주소가 달라짐 | 분기 예측, 파이프라인 Flush |

### 4) 분기 예측

* **정적 분기 예측**: 실행 이력과 무관한 고정 규칙을 사용한다.
* **동적 분기 예측**: 실제 분기 결과 등 과거 실행 이력을 활용한다.

분기 예측 실패 시 잘못된 경로에서 가져온 명령어를 제거하는 동작을 **Flush**라고 한다.

낭비되는 사이클은 분기 결과를 확인하는 시점과 제거되는 파이프라인 단계에 따라 달라진다. 문제에서 Fetch와 Decode만 Flush된다고 주어지면 해당 조건에 맞춰 계산한다.

### 5) CPI와 실행 시간

* CPI(Cycles Per Instruction): 명령어 하나당 평균 사이클 수
* IPC(Instructions Per Cycle): 한 사이클당 평균 완료 명령어 수

이상적인 관계는 다음과 같다.

$$
IPC\approx\frac{1}{CPI}
$$

실행 시간은 다음과 같이 계산한다.

$$
CPU\ Time=Instruction\ Count\times CPI\times Cycle\ Time
$$

또는

$$
CPU\ Time=\frac{Instruction\ Count\times CPI}{Clock\ Rate}
$$

명령어당 1사이클의 Stall이 발생할 확률이 \(p\)이고 기본 CPI가 \(C\)라면, 해당 조건에서 평균 CPI는 다음과 같다.

$$
CPI=C+p
$$

예를 들어 기본 CPI가 5이고 15% 확률로 1사이클 Stall이 발생한다면 평균 CPI는 \(5.15\)다.

총 실행 사이클이 12,000이라면 완료 명령어 수는 약 \(12000/5.15\approx2330\)개다.

## 2.4 명령어·데이터 흐름과 기억장치 구조

### 1) Flynn 분류

명령어 흐름과 데이터 흐름의 수로 컴퓨터 구조를 구분하는 방식이다.

| 분류 | 명령어 흐름 | 데이터 흐름 | 예시                   |
| ---- | ------ | ------ | -------------------- |
| SISD | 1      | 1      | 일반적인 단일 프로세서        |
| SIMD | 1      | 다수     | 벡터 처리, GPU의 병렬 연산    |
| MISD | 다수     | 1      | 실제 사례가 드문 분류         |
| MIMD | 다수     | 다수     | 멀티코어, 다중 프로세서 시스템   |

### 2) von Neumann 구조와 Harvard 구조

* **von Neumann 구조**: 명령어와 데이터를 같은 메모리에 보관한다.
* **Harvard 구조**: 명령어 메모리와 데이터 메모리를 분리한다.

Flynn 분류는 명령어·데이터 흐름의 수를 기준으로 하고, Harvard 구조는 명령어·데이터 메모리의 분리 여부를 기준으로 하므로 서로 다른 분류 축이다. MIMD와 Harvard 구조를 같은 기준으로 비교하지 않도록 주의한다.

# 3. 컴퓨터 기억 및 입출력장치

## 3.1 기억장치 계층 구조

일반적인 기억장치 계층은 다음과 같다.

**레지스터 → 캐시 → 주기억장치(RAM) → 보조기억장치(SSD/HDD)**

위쪽으로 갈수록 일반적으로 접근 속도가 빠르고 용량은 작으며, 비트당 비용이 높다.

| 장치        | 특징                                  |
| --------- | ----------------------------------- |
| 레지스터      | CPU 내부의 매우 빠른 저장 공간                 |
| SRAM      | 빠르고 비싸며 일반적으로 캐시에 사용                |
| DRAM      | 집적도가 높고 주기적으로 Refresh 필요, 주기억장치에 사용 |
| ROM/Flash | 전원이 꺼져도 데이터 유지                      |
| SSD       | 플래시 메모리 기반 보조기억장치                   |
| HDD       | 자기 디스크 기반 보조기억장치                    |

### 1) RAM과 ROM

* **RAM**: 일반적으로 읽기·쓰기가 가능하고 휘발성 메모리로 사용된다.
* **ROM**: 비휘발성 메모리 계열을 의미하며 펌웨어 등의 저장에 사용된다.
* **Flash Memory**: 전원이 꺼져도 데이터를 유지하고 전기적으로 지우고 기록할 수 있다.

### 2) 연관기억장치(Associative Memory)

연관기억장치는 주소 대신 저장된 내용의 일부를 기준으로 일치하는 항목을 찾는 방식이다.

* 내용 주소화 메모리(Content Addressable Memory, CAM)라고도 한다.
* 여러 항목을 병렬로 비교해 검색할 수 있다.
* 빠른 검색이 가능하지만 구현 비용과 하드웨어 복잡도가 커질 수 있다.

일반적인 주소 기반 메모리 접근과 구분한다.

## 3.2 캐시 메모리

### 1) 캐시의 기본 개념

캐시는 CPU와 주기억장치 사이에서 자주 사용하는 데이터를 보관해 평균 메모리 접근 시간을 줄이는 고속 메모리다.

* **캐시 적중(Hit)**: 요청한 데이터가 캐시에 존재한다.
* **캐시 미스(Miss)**: 요청한 데이터가 캐시에 없다.
* **적중률(Hit Rate)**: 전체 접근 중 적중한 비율
* **미스율(Miss Rate)**: 전체 접근 중 실패한 비율

$$
Miss\ Rate=1-Hit\ Rate
$$

캐시의 성능은 접근 시간과 미스 발생 시 추가 비용에 영향을 받는다.

### 2) 사상 방식

| 방식                          | 특징                         |
| --------------------------- | -------------------------- |
| 직접 사상(Direct Mapped)        | 각 메모리 블록이 정해진 캐시 위치에 대응    |
| 완전 연관 사상(Fully Associative) | 메모리 블록을 캐시의 어느 위치에도 저장 가능  |
| 집합 연관 사상(Set Associative)   | 정해진 집합 내 여러 위치 중 하나에 저장 가능 |

### 3) Tag, Index, Offset

주소는 일반적으로 다음 세 부분으로 나눌 수 있다.

* **Offset**: 블록 안의 바이트 위치
* **Index**: 캐시의 블록 또는 집합 위치 선택
* **Tag**: 해당 위치에 저장된 메모리 블록이 맞는지 확인

직접 사상 캐시에서:

$$
Offset=\log_2(Block\ Size)
$$

$$
Index=\log_2\left(\frac{Cache\ Size}{Block\ Size}\right)
$$

$$
Tag=Address\ Bits-Index-Offset
$$

예시: 32비트 주소, 캐시 32KB, 블록 64B

* 캐시 크기: \(2^{15}\)B
* 블록 크기: \(2^6\)B
* 블록 개수: \(2^{15}/2^6=2^9=512\)
* Offset: 6비트
* Index: 9비트
* Tag: \(32-6-9=17\)비트

### 4) 캐시 쓰기 정책

* **Write Through**: 캐시에 쓴 데이터를 주기억장치에도 즉시 반영한다.
* **Write Back**: 캐시에 먼저 기록하고, 해당 블록이 교체될 때 변경 내용을 반영할 수 있다.
* **Write Allocate**: 쓰기 미스 시 해당 블록을 캐시에 가져온다.
* **No Write Allocate**: 쓰기 미스 시 캐시에 블록을 적재하지 않고 하위 메모리에 기록하는 방식이다.

### 5) 지역성(Locality)

* **시간 지역성**: 최근 접근한 데이터를 다시 접근할 가능성이 높다.
* **공간 지역성**: 접근한 주소 주변의 데이터에 접근할 가능성이 높다.

캐시는 이러한 지역성을 활용한다.

## 3.3 입출력 제어

### 1) 프로그램 입출력

CPU가 입출력 장치의 상태를 확인하고 데이터 전송을 직접 제어한다. 구조는 단순하지만 CPU의 개입이 많아질 수 있다.

### 2) 인터럽트 기반 입출력

장치가 처리가 필요하거나 완료되었을 때 인터럽트를 발생시켜 CPU에 알린다.

인터럽트 처리의 일반적인 흐름:

1. 인터럽트 발생
2. 현재 실행 상태 저장
3. 인터럽트 서비스 루틴(ISR) 실행
4. 장치 또는 인터럽트 원인 처리
5. 저장한 실행 상태 복구 후 복귀

### 3) 인터럽트 폴링

인터럽트 처리 루틴 등에서 여러 장치의 상태를 순차적으로 확인하여 어떤 장치가 요청했는지 판별하는 방식이다.

* 장치 상태를 순서대로 확인한다.
* 구현이 단순하다.
* 확인해야 할 장치가 많으면 판별 시간이 길어질 수 있다.

폴링 자체는 장치 상태를 반복 확인하는 방식이며, 인터럽트 발생 장치를 찾기 위한 폴링과 일반적인 주기적 폴링을 문맥에 따라 구분한다.

### 4) DMA(Direct Memory Access)

CPU가 모든 데이터를 직접 복사하지 않고 DMA 컨트롤러가 메모리와 입출력 장치 사이의 데이터 전송을 담당하는 방식이다.

동작 과정:

1. CPU가 DMA 컨트롤러에 주소, 전송 크기, 전송 방향 등을 설정한다.
2. DMA 컨트롤러가 데이터 전송을 수행한다.
3. 전송이 완료되면 일반적으로 인터럽트로 CPU에 알린다.

**암기:** CPU 설정 → DMA 직접 전송 → 완료 알림

### 5) 채널(Channel)

입출력 채널은 CPU의 입출력 부담을 줄이기 위해 입출력 작업을 수행하거나 제어하는 별도 기능 또는 장치다.

DMA는 주로 데이터 블록의 직접 전송에 초점을 맞추고, 입출력 채널은 입출력 작업의 제어와 수행을 더 폭넓게 담당할 수 있다. 세부 구조는 컴퓨터 시스템에 따라 다르다.

# 4. 자료구조 활용

## 4.1 기본 자료구조

### 1) 배열과 연결 리스트

| 구분     | 배열                      | 연결 리스트                   |
| ------ | ----------------------- | ------------------------ |
| 메모리 배치 | 연속된 공간                  | 노드가 포인터로 연결              |
| 임의 접근  | 인덱스로 빠르게 접근, 일반적으로 O(1) | 앞에서부터 탐색, 일반적으로 O(n)     |
| 삽입·삭제  | 중간 삽입 시 원소 이동이 필요할 수 있음 | 위치를 알고 있다면 링크 변경으로 처리 가능 |
| 크기     | 일반 배열은 고정 크기인 경우가 많음    | 노드 추가·삭제로 크기 변경 가능       |

연결 리스트 종류:

* 단순 연결 리스트
* 이중 연결 리스트
* 원형 연결 리스트

### 2) 스택(Stack)

LIFO(Last In, First Out): 마지막에 들어간 데이터가 먼저 나온다.

| 연산        | 의미               |
| --------- | ---------------- |
| Push      | 데이터 삽입           |
| Pop       | 최상단 데이터 제거 및 반환  |
| Peek/Top  | 최상단 데이터 확인       |
| Overflow  | 스택 용량 초과         |
| Underflow | 비어 있는 스택에서 제거 시도 |

사용 예시: 함수 호출, 재귀, 괄호 검사, 깊이 우선 탐색(DFS).

함수 호출 스택에는 일반적으로 복귀 주소, 지역변수, 저장 레지스터 등의 정보가 포함될 수 있다.

### 3) 큐(Queue)

FIFO(First In, First Out): 먼저 들어간 데이터가 먼저 나온다.

| 종류       | 특징                    |
| -------- | --------------------- |
| 일반 큐     | 먼저 들어온 데이터부터 처리       |
| 원형 큐     | 배열의 끝과 시작을 연결해 공간 재사용 |
| 덱(Deque) | 양쪽 끝에서 삽입·삭제          |
| 우선순위 큐   | 우선순위에 따라 원소를 꺼냄       |

사용 예시: 작업 대기열, 버퍼, 너비 우선 탐색(BFS).

### 4) 트리와 이진 트리

트리는 계층적 구조를 표현하는 자료구조다.

* 루트(Root): 최상위 노드
* 부모·자식 노드: 계층 관계
* 리프(Leaf): 자식이 없는 노드
* 깊이(Depth): 루트에서 해당 노드까지의 간선 수
* 높이(Height): 해당 노드에서 가장 깊은 리프까지의 간선 수

이진 트리는 각 노드가 최대 두 개의 자식을 갖는 트리다.

**순회 방식**

* 전위 순회: Root → Left → Right
* 중위 순회: Left → Root → Right
* 후위 순회: Left → Right → Root
* 레벨 순회: 깊이 순서로 방문

이진 탐색 트리(BST)는 일반적으로 왼쪽 서브트리에 작은 값, 오른쪽 서브트리에 큰 값을 배치한다. 균형이 무너지면 탐색 성능이 O(n)까지 나빠질 수 있다.

### 5) 균형 이진 탐색 트리

| 종류             | 핵심 특징                                          |
| -------------- | ---------------------------------------------- |
| AVL Tree       | 각 노드의 좌우 서브트리 높이 차이가 최대 1이 되도록 유지              |
| Red-Black Tree | 노드 색상 규칙을 이용해 높이 균형을 제한                        |
| B-Tree         | 여러 키와 자식을 갖는 균형 탐색 트리                          |
| B+ Tree        | 실제 데이터 또는 레코드 참조를 주로 리프에 배치하고 리프를 연결하는 형태가 일반적 |

AVL 트리는 엄격한 높이 균형을 유지한다. Red-Black Tree는 상대적으로 느슨한 균형 조건을 사용한다.

## 4.2 정렬 및 탐색

### 1) 주요 정렬 알고리즘

| 알고리즘  |      평균 시간 |      최악 시간 | 특징                 |
| ----- | ---------: | ---------: | ------------------ |
| 버블 정렬 |      O(n²) |      O(n²) | 인접 원소 비교·교환        |
| 선택 정렬 |      O(n²) |      O(n²) | 최솟값을 선택해 배치        |
| 삽입 정렬 |      O(n²) |      O(n²) | 정렬된 구간에 삽입         |
| 병합 정렬 | O(n log n) | O(n log n) | 분할 정복, 추가 메모리 사용   |
| 퀵 정렬  | O(n log n) |      O(n²) | 피벗 기준 분할           |
| 힙 정렬  | O(n log n) | O(n log n) | 힙 자료구조 이용          |
| 계수 정렬 |     O(n+k) |     O(n+k) | 정수 값의 범위 \(k\)를 활용 |

정렬 알고리즘의 안정성은 값이 같은 원소들의 상대적인 순서가 유지되는지를 뜻한다. 병합 정렬과 삽입 정렬은 일반적인 구현에서 안정 정렬이 가능하고, 퀵 정렬과 힙 정렬은 일반적으로 불안정 정렬이다.

### 2) 비교 기반 정렬의 하한

비교 결과만으로 순서를 결정하는 일반적인 정렬 알고리즘은 최악의 경우 \(\Omega(n\log n)\)번의 비교가 필요하다.

표기법 구분:

* **O(f(n))**: 점근적 상한
* **Ω(f(n))**: 점근적 하한
* **Θ(f(n))**: 점근적으로 같은 차수의 상한과 하한

따라서 비교 기반 정렬의 하한을 묻는 문제에서는 \(O(n\log n)\)이 아니라 \(\Omega(n\log n)\)이라고 답해야 한다.

### 3) 탐색 알고리즘

| 알고리즘   | 시간 복잡도               | 조건 및 특징             |
| ------ | -------------------- | ------------------- |
| 선형 탐색  | O(n)                 | 정렬되지 않은 데이터에도 사용 가능 |
| 이진 탐색  | O(log n)             | 데이터가 정렬되어 있어야 함     |
| BST 탐색 | 평균 O(log n), 최악 O(n) | 트리의 균형 상태에 영향       |
| 해시 탐색  | 평균 O(1), 최악 O(n) 가능  | 충돌 처리 방식에 영향        |

## 4.3 그래프와 그래프 탐색

### 1) 그래프의 구성

그래프는 정점(Vertex)과 간선(Edge)으로 구성된다.

* 방향 그래프 / 무방향 그래프
* 가중치 그래프 / 비가중치 그래프
* 연결 그래프 / 비연결 그래프
* 순환 그래프 / 비순환 그래프

**인접 행렬**

* 공간 복잡도: O(V²)
* 두 정점 사이 간선 존재 여부 확인이 빠름
* 간선이 적은 희소 그래프에서는 공간 낭비가 발생할 수 있음

**인접 리스트**

* 일반적으로 O(V+E) 공간
* 간선이 적은 그래프에 유리
* 특정 두 정점 사이의 간선 확인은 구현에 따라 시간이 더 필요할 수 있음

### 2) DFS와 BFS

| 구분      | DFS                 | BFS              |
| ------- | ------------------- | ---------------- |
| 방식      | 한 경로를 깊게 탐색         | 가까운 정점부터 탐색      |
| 주요 자료구조 | 스택 또는 재귀            | 큐                |
| 활용      | 사이클 탐지, 위상 정렬 등의 기반 | 무가중치 그래프 최단 경로   |
| 복잡도     | 인접 리스트 기준 O(V+E)    | 인접 리스트 기준 O(V+E) |

### 3) 최단 경로 알고리즘

* **Dijkstra**: 음수 가중치가 없는 그래프에서 최단 경로 탐색
* **Bellman-Ford**: 음수 가중치를 처리할 수 있고 음수 사이클 탐지에 활용
* **Floyd-Warshall**: 모든 정점 쌍의 최단 거리를 계산
* **A***: 실제 누적 비용 \(g(n)\)과 목표까지의 추정 비용 \(h(n)\)을 활용

A*의 평가 함수:

$$
f(n)=g(n)+h(n)
$$

휴리스틱이 \(h(n)=0\)이면 누적 비용 \(g(n)\)만을 기준으로 탐색하므로 적절한 비음수 간선 조건에서 Dijkstra와 같은 탐색 방식이 된다.

A*의 휴리스틱이 최단 경로를 보장하는지 판단할 때는 허용성(Admissibility) 등 조건을 함께 확인해야 한다.

### 4) 위상 정렬과 최소 신장 트리

* **위상 정렬**: 방향 비순환 그래프(DAG)의 정점을 간선 방향을 지키도록 나열한다.
* **최소 신장 트리(MST)**: 연결된 무방향 가중치 그래프에서 모든 정점을 연결하는 간선들의 총 가중치가 최소인 트리다.
* **Kruskal**: 간선 가중치 순서로 선택하며 사이클을 방지한다.
* **Prim**: 하나의 정점에서 시작해 트리를 확장한다.

## 4.4 인덱스와 해싱

### 1) 인덱스

인덱스는 특정 키를 기준으로 데이터의 위치를 빠르게 찾도록 돕는 자료구조다.

* 탐색 성능을 높일 수 있다.
* 별도의 저장 공간이 필요하다.
* 데이터 삽입·수정·삭제 시 인덱스 유지 비용이 발생할 수 있다.
* 데이터베이스에서는 B-Tree 또는 B+ Tree 계열 인덱스를 많이 활용한다.

### 2) 해시 테이블

해시 함수는 키를 배열의 인덱스 등으로 변환한다.

$$
Index=h(Key)
$$

서로 다른 키가 같은 위치로 변환되면 **충돌(Collision)**이 발생한다.

대표적인 충돌 해결 방식:

* **Separate Chaining**: 각 슬롯에 연결 리스트 등 별도 자료구조를 연결한다.
* **Open Addressing**: 테이블 내부의 다른 슬롯을 찾아 저장한다.

  * 선형 조사(Linear Probing)
  * 이차 조사(Quadratic Probing)
  * 이중 해싱(Double Hashing)

### 3) 적재율(Load Factor)

$$
\alpha=\frac{\text{저장된 원소 수}}{\text{전체 슬롯 수}}
$$

예를 들어 전체 슬롯이 200개이고 저장된 원소가 150개라면 적재율은 0.75다.

Open Addressing에서는 적재율이 높아질수록 빈 슬롯을 찾기 어려워지는 경향이 있다. Separate Chaining에서는 적재율이 1을 넘을 수도 있다.

### 4) 해시 테이블과 다른 자료구조 비교

* 해시 테이블: 평균적인 키 탐색이 빠르지만 순서 기반 범위 검색에는 불리하다.
* 균형 이진 탐색 트리: 탐색·삽입·삭제를 O(log n) 수준으로 유지할 수 있고 정렬 순회가 가능하다.
* 배열: 인덱스 접근은 빠르지만 중간 삽입·삭제에 비용이 발생할 수 있다.

# 5. 프로그래밍 언어 활용

## 5.1 구조적 프로그래밍 언어

구조적 프로그래밍은 프로그램을 명확한 제어 구조로 구성해 이해와 유지보수를 쉽게 하는 방식이다.

주요 제어 구조:

* 순차 구조: 명령어를 순서대로 실행
* 선택 구조: 조건에 따라 분기
* 반복 구조: 조건 또는 횟수에 따라 반복

대표적인 언어로 C가 있으며, 조건문과 반복문을 사용해 알고리즘을 표현한다.

### 주요 제어문

| 구조  | C 예시                          |
| --- | ----------------------------- |
| 조건문 | `if`, `else`, `switch`        |
| 반복문 | `for`, `while`, `do-while`    |
| 분기  | `break`, `continue`, `return` |

* `break`: 가장 가까운 반복문 또는 `switch` 등을 종료한다.
* `continue`: 반복문의 다음 반복으로 이동한다.
* `return`: 함수 실행을 종료하고 호출 지점으로 돌아간다.

## 5.2 객체지향 프로그래밍 언어

### 1) 객체지향 핵심 개념

| 개념  | 의미                             |
| --- | ------------------------------ |
| 캡슐화 | 데이터와 관련 동작을 묶고 접근을 제어          |
| 상속  | 기존 클래스의 속성과 동작을 물려받아 확장        |
| 다형성 | 같은 인터페이스나 호출 형태가 서로 다른 구현으로 동작 |
| 추상화 | 핵심 특성을 표현하고 불필요한 세부 사항을 감춤     |

### 2) 오버로딩과 오버라이딩

* **오버로딩(Overloading)**: 같은 이름의 메서드를 서로 다른 매개변수 목록으로 정의한다.
* **오버라이딩(Overriding)**: 하위 클래스가 상위 클래스의 메서드를 재정의한다.

Java에서는 반환형만 다르게 한 메서드 선언으로 오버로딩할 수 없다.

### 3) 추상 클래스와 인터페이스

* 추상 클래스: 인스턴스화할 수 없으며 추상 메서드와 일반 메서드 등을 가질 수 있다.
* 인터페이스: 구현해야 할 동작의 계약을 정의하는 데 사용한다. Java의 인터페이스는 기본 메서드 등도 지원한다.
* 추상 메서드를 구현하지 않은 구체 클래스는 일반적으로 컴파일 오류가 발생한다.

### 4) 예외 처리

* `try`: 예외가 발생할 수 있는 코드를 실행한다.
* `catch`: 발생한 예외를 처리한다.
* `finally`: 일반적으로 예외 발생 여부와 관계없이 실행되는 정리 코드에 사용한다.
* `throw`: 예외를 발생시킨다.
* `throws`: 메서드가 던질 수 있는 예외를 선언한다.

Java의 `Exception`과 `Error`는 모두 `Throwable`의 하위 타입이지만 의미와 처리 목적이 다르다.

### 3) 오류 분류 문제 풀이

문제에서 오류가 발생한 시점을 확인한다.

* 프로그램이 실행되기 전 문법이나 타입 검사에서 발견: 컴파일 또는 구문 단계 오류
* 실행 중 예외가 발생: 런타임 오류
* 오류 없이 실행되지만 결과가 잘못됨: 논리 오류

언어마다 컴파일과 실행 방식이 다르므로, 문제에서 지정한 언어를 기준으로 판단한다.

### 4) 테스트 오라클

테스트 오라클(Test Oracle)은 테스트 결과가 올바른지 판단하는 기준 또는 메커니즘이다.

예상 결과와 실제 결과를 비교해 정답 여부를 판단할 수 있다.

관련 용어:

* **테스트 케이스**: 입력, 실행 조건, 예상 결과 등을 포함하는 테스트 단위
* **테스트 오라클**: 결과의 정확성을 판단하는 기준
* **테스트 데이터**: 테스트 실행에 사용하는 입력 데이터
* **테스트 드라이버**: 시험 대상 모듈을 호출하는 프로그램
* **테스트 스텁**: 시험 대상이 호출하는 하위 모듈을 대체하는 구성 요소

## 5.4 화이트박스 테스트와 순환 복잡도

### 1) McCabe 순환 복잡도

흐름 그래프의 논리적 복잡도를 수치로 나타낸 지표다.

$$
V(G)=E-N+2P
$$

* \(E\): 간선(Edge) 수
* \(N\): 노드(Node) 수
* \(P\): 연결 요소 수 (하나로 연결된 그래프라면 \(P=1\))

연결 요소가 1개이면 다음과 같이 간단해진다.

$$
V(G)=E-N+2
$$

판단 지점(조건문·반복문 등 단순 조건)만 셀 때는 다음 관계도 활용할 수 있다.

$$
V(G)=\text{판단 지점 수}+1
$$

예시: 단순 조건 `if`가 2개인 흐름이라면 판단 지점이 2개이므로 \(V(G)=3\)이다. 복합 조건(`&&`, `||` 등)의 계산은 문제의 조건 제시 방식에 따라 달라지므로 조건식을 확인해야 한다.

### 2) 테스트 커버리지

* **문장 커버리지**: 모든 문장을 한 번 이상 실행하는지 확인한다.
* **분기 커버리지**: 모든 판단 지점의 참·거짓 분기를 실행하는지 확인한다.
* **조건 커버리지**: 개별 조건식의 참·거짓 조합을 실행하는지 확인한다.

일반적으로 뒤로 갈수록 엄격한 기준이며, 순환 복잡도는 필요한 독립 테스트 경로 수의 기준이 된다.

# 6. 네트워크 프로토콜 분석

## 6.1 OSI 7계층

| 계층 | 이름        | 주요 기능                  | 대표 프로토콜·기술          |
| -: | --------- | ---------------------- | ------------------- |
|  7 | 응용 계층     | 응용 서비스 제공              | HTTP, DNS, SMTP     |

|  4 | 전송 계층     | 종단 간 전송, 포트, 신뢰성·흐름 제어 | TCP, UDP            |
|  3 | 네트워크 계층   | 논리 주소 및 라우팅            | IP, ICMP            |
|  2 | 데이터 링크 계층 | 프레임, MAC 주소, 링크 접근     | Ethernet, Wi-Fi MAC |

TCP/IP 모델은 자료에 따라 4계층 또는 5계층으로 표현될 수 있다. OSI 7계층과 이름을 일대일로 그대로 대응시키기보다는 각 모델의 기능을 기준으로 이해한다.

## 6.2 TCP/IP와 주요 프로토콜

### 1) TCP와 UDP

| 구분    | TCP                | UDP                          |
| ----- | ------------------ | ---------------------------- |
| 연결    | 연결 지향              | 비연결형                         |
| 신뢰성   | 순서·재전송·오류 복구 등을 지원 | 자체적으로 전달·순서 보장을 제공하지 않음      |
| 흐름 제어 | 지원                 | TCP와 같은 종단 간 흐름 제어 없음        |
| 혼잡 제어 | 지원                 | 기본 UDP 자체에는 TCP와 같은 혼잡 제어 없음 |
| 오버헤드  | 상대적으로 큼            | 상대적으로 작음                     |
| 사용 예  | 웹, 파일 전송, 이메일      | DNS 질의, 실시간 미디어, 일부 게임 통신    |

UDP를 사용한다고 해서 애플리케이션에서 신뢰성이나 혼잡 제어를 구현할 수 없는 것은 아니다. 필요한 기능은 상위 프로토콜에서 추가할 수 있다.

### 2) 흐름 제어·혼잡 제어·오류 제어

| 구분    | 목적                           | 대표적인 방식                    |
| ----- | ---------------------------- | -------------------------- |
| 흐름 제어 | 송신자가 수신자의 처리 능력을 초과하지 않도록 조절 | TCP 수신 윈도우, Sliding Window |
| 혼잡 제어 | 네트워크 전체의 과도한 트래픽과 혼잡 완화      | TCP Congestion Control     |
| 오류 제어 | 데이터 손상·손실을 탐지하고 복구           | 체크섬, ACK, 재전송 등            |

**흐름 제어와 혼잡 제어를 혼동하지 말 것.**

* 수신 버퍼가 감당할 수 있는 양보다 송신 속도가 빠른 문제 → 흐름 제어
* 네트워크 경로의 용량을 초과해 패킷 손실과 지연이 증가하는 문제 → 혼잡 제어
* 패킷 손실이나 손상에 대한 검출·복구 → 오류 제어 관련 기능

### 3) TCP의 주요 개념

* **3-way Handshake**: 연결 설정 과정

  1. SYN
  2. SYN-ACK
  3. ACK
* **Sequence Number**: 전송 데이터의 순서를 관리하는 데 사용
* **Acknowledgment Number**: 상대방에게 다음으로 기대하는 바이트 번호를 나타내는 데 사용
* **재전송**: 손실이 의심되는 데이터를 다시 전송
* **수신 윈도우**: 수신 측이 받아들일 수 있는 데이터 양을 광고하는 데 사용

TCP는 바이트 스트림을 제공하므로 애플리케이션의 메시지 경계를 그대로 보존하지 않는다.

### 4) 주요 응용 계층 프로토콜

| 프로토콜   | 용도                   |  일반적인 기본 포트 |
| ------ | -------------------- | ----------: |
| HTTP   | 웹 통신                 |          80 |
| HTTPS  | TLS를 이용한 보호된 HTTP 통신 |         443 |
| FTP    | 파일 전송                | 21 제어 연결, 20 데이터 연결 |
| SSH    | 보안 원격 접속             |          22 |
| Telnet | 원격 터미널 접속            |          23 |
| SMTP   | 이메일 전송               |          25 |
| DNS    | 도메인 이름 해석            | 53 (UDP 위주, 영역 전송 등은 TCP) |
| DHCP   | IP 설정 자동 할당          | 67/68 UDP (서버 67, 클라이언트 68) |
| POP3   | 이메일 수신               |         110 |
| IMAP   | 이메일 접근·동기화           |         143 |
| NTP    | 시간 동기화               |     123 UDP |
| SNMP   | 네트워크 관리              | 161/162 UDP (관리 161, 트랩 162) |

포트 번호는 기본적으로 널리 알려진 값이며 실제 서비스 구성에서 변경될 수 있다.

## 6.3 네트워크 주소와 구성 요소

### 1) IP와 MAC 주소

* **IP 주소**: 네트워크 계층에서 사용하는 논리 주소
* **MAC 주소**: 데이터 링크 계층에서 링크 내 장치를 식별하는 데 사용하는 주소
* **포트 번호**: 전송 계층에서 애플리케이션 또는 통신 종단점을 구분하는 데 사용

### 2) 네트워크 장비

| 장비           | 주요 역할                              |
| ------------ | ---------------------------------- |
| Hub          | 수신 신호를 여러 포트로 전달                   |
| Switch       | 주로 MAC 주소를 바탕으로 프레임 전달             |
| Router       | IP 주소와 라우팅 정보를 바탕으로 패킷 전달          |
| Gateway      | 서로 다른 프로토콜이나 네트워크 환경 사이의 연결 기능을 제공 |
| Access Point | 무선 단말의 네트워크 접속을 제공                 |
| Firewall     | 규칙에 따라 네트워크 트래픽을 허용 또는 차단          |

### 3) IPv4 서브넷

IPv4 주소는 32비트다. 서브넷 마스크 또는 CIDR 프리픽스는 네트워크 부분과 호스트 부분을 구분한다.

예를 들어 `/24`는 앞의 24비트가 네트워크 프리픽스임을 뜻한다.

일반적인 IPv4 서브넷에서 호스트 주소 수는 다음과 같이 계산할 수 있다.

$$
2^{32-p}-2
$$

여기서 \(p\)는 프리픽스 길이다. 이 식은 일반적인 브로드캐스트 서브넷을 전제로 하며 `/31`, `/32` 등의 특수한 경우는 별도 규칙을 고려해야 한다.

## 6.4 네트워크 패킷 분석

### 1) 캡슐화

송신 측에서 데이터는 계층별 헤더 등이 추가되어 전달된다.

* 응용 데이터
* 전송 계층 세그먼트(TCP) 또는 데이터그램(UDP)
* 네트워크 계층 패킷(IP)
* 데이터 링크 계층 프레임
* 물리 계층의 비트·신호

수신 측은 반대 방향으로 각 계층의 헤더를 해석한다.

### 2) Wireshark에서 확인할 항목

* 송신지·목적지 IP 주소
* 송신지·목적지 포트
* TCP Flags: SYN, ACK, FIN, RST 등
* Sequence Number 및 ACK Number
* 재전송 여부
* RTT와 응답 지연
* 패킷 크기와 전송 간격
* DNS 질의와 응답
* 연결 설정 및 종료 과정

패킷 캡처에서 재전송이 관찰되더라도 원인을 즉시 단정하면 안 된다. 실제 손실, 혼잡, 지연, 캡처 위치, 오프로딩 기능 등에 따라 관측 결과가 달라질 수 있다.

### 3) 프로토콜 간 연계 예시

웹 페이지 접속을 단순화하면 다음과 같다.

1. DNS로 도메인 이름을 IP 주소로 해석한다.
2. 목적지 IP와 라우팅 정보를 이용해 패킷을 전달한다.
3. TCP 연결이 필요한 경우 연결을 설정한다.
4. HTTPS라면 TLS 연결을 통해 통신을 보호한다.
5. HTTP 요청과 응답을 주고받는다.
6. TCP가 데이터 전달과 순서 관리 등을 담당한다.

이처럼 실제 네트워크 통신은 여러 계층과 프로토콜이 연계되어 동작한다.

# 7. 기출 기반 필수 공식 및 빠른 암기

| ---------------- | ------------------------------------- |
| 주소선 개수           | \(n=\log_2 N\)                        |
| 주소 가능한 개수        | \(N=2^n\)                             |
| 평균 CPI           | 기본 CPI + 기대 Stall 사이클                 |

| 캐시 Offset        | \(\log_2(\text{블록 크기})\)              |

# 8. 기출에서 자주 혼동하는 개념

1. **흐름 제어 vs 혼잡 제어**: 수신자 보호와 네트워크 혼잡 완화를 구분한다.
2. **중첩 호출 vs 재귀 호출**: 다른 서브루틴 호출과 자기 자신 호출을 구분한다.
3. **정적 vs 동적 분기 예측**: 실행 이력을 사용하는지 확인한다.
4. **CPI vs IPC**: 명령어당 사이클과 사이클당 명령어 수를 구분한다.
5. **캐시 Tag / Index / Offset**: 블록 크기와 블록 개수를 각각 계산한다.
6. **DMA vs 인터럽트 입출력**: 데이터 전송을 누가 수행하고 CPU가 어떻게 통지받는지 구분한다.
7. **스택 vs 큐**: LIFO와 FIFO를 구분한다.
8. **AVL vs Red-Black Tree**: 균형을 유지하는 규칙이 다르다.
9. **O vs Ω vs Θ**: 상한, 하한, 점근적으로 같은 차수를 구분한다.
10. **A* vs Dijkstra**: A*는 휴리스틱을 추가로 사용하며 \(h(n)=0\)이면 Dijkstra와 같은 방식이 된다.
11. **MIMD vs Harvard 구조**: Flynn 분류는 명령어·데이터 흐름의 수를, Harvard 구조는 명령어·데이터 메모리의 분리 여부를 기준으로 한다.
12. **인터럽트 폴링 vs 인터럽트 벡터**: 폴링은 발생 장치를 순차적으로 확인하고, 벡터 방식은 인터럽트 원인에 따라 처리 위치를 식별하는 방식이다.
